# DECISIONS — Layout Spec + Design Decisions

## Layout spec (user-provided text; reference image unreadable)
Anchors for ScreenShell (full rect 0..1):
- **HeaderBar**: rect(0, 0, 1, 0.16) — player status: avatar, name, level + XP bar, coins, gems
- **MainContentHost**: y [0.16 → 0.76], full width — progression ladder / next challenge
- **NavBar**: y [0.76 → 0.91], full width — button order: Profile, Social, Home, Special, Settings
- **LeftZone**: x [0, 0.18], y [0.22, 0.62] — timed events (RemoteConfig.get_events()); overlaps main content, rendered on top
- **RightZone**: x [0.82, 1.0], y [0.22, 0.62] — offers: piggy bank, daily gift, boosters; on top
- **BannerSlot**: y [0.91 → 1.0], full width — AdManager creative strip
- L/R zones visible ONLY on Home; hidden on all other screens and fullscreen game/results.

## Decisions made (autonomous — user said don't ask unless unanswerable)
- **Code-first UI**: minimal .tscn files, build UI in GDScript. No hardcoded colors — ThemeFactory generates the theme resource.
- **Theme palette**: bg #10141f, panel #1b2233, accent gold #f5c542, blue #4f8cff, text primary #eef2fb / secondary #9aa7c7; SILENCE_DB = -80.
- **Theme variation naming (VERIFIED against Godot 4.7 source)**: `Theme.set_type_variation` only accepts ASCII identifier names `[A-Za-z0-9_]` — slashes are rejected (`is_valid_type_name` → `is_ascii_identifier_char`; official test checks `"With/Slash"` fails). Use plain PascalCase names, exactly like Godot's built-in themes (`HeaderSmall`, `FlatButton`). Ours: **LabelDim, LabelGold, LabelTitle, ButtonPrimary, ButtonAccent, ButtonNav, PanelZone, PanelAvatar**. UI consumes them via the **`theme_type_variation`** property (NOT `theme_type`) on Controls. In .tres files items serialize as `<Variation>/<category>/<item>` (e.g. `LabelDim/colors/font_color`) and each variation carries a `<Variation>/base_type` key — first slash is the separator, so plain names are unambiguous.
- **AdManager design** (core/ad_manager.gd): banner state machine idle → loading → loaded (+ error); signal `banner_state_changed(state: String, creative: Dictionary)`; 3 mock creatives {id, title, body, color_hex} rotating on refresh; respects RemoteConfig `banner_ads_enabled` flag + `banner_refresh_sec`; `_generation` counter cancels in-flight awaits when stop() called; Timer child for auto-refresh; test hooks set_load_delay/set_failure_rate; public start()/stop()/get_state()/get_current_creative()/is_enabled(); tracks `ad_impression` via Analytics.
- **GameResult**: class_name RefCounted {stage_id, score, best_score, is_new_best, coins_earned, xp_earned, won, duration_sec} + `to_dict()` (the `gameplay_finished` signal is Dictionary-typed); coins = score/10 × results_coin_multiplier (remote experiment).
- **Gameplay demo**: tap-target game, round_duration_sec (30s) from config; spawn interval from `target_spawn_rate` experiment params (spawn_interval_min/max, swap-guarded); targets live target_lifetime_sec; tap = combo points (`Scoring.tap_score(chain)` = 10 + chain×2), expiry resets chain; pauseable via delta accumulation (not process freeze) so pause menu works.
- **Game flow signal ordering (CRITICAL)**: Godot signals are synchronous — in GameScreen `_on_round_ended`, emit `navigation_requested(RESULTS)` FIRST (ScreenManager synchronously creates + mounts ResultsScreen, whose `_ready` connects to `gameplay_finished`), THEN emit `gameplay_finished(result.to_dict())`. Reverse order = ResultsScreen never receives the data. ResultsScreen also caches its last result so re-navigation without a new round still renders something.
- **Boot order in main.gd (implemented)**: SaveSystem.load_save() → SettingsManager.init_from_save() → LocalizationManager.init() → RemoteConfig.fetch() → Analytics.start_session() → AdManager.start() → ScreenManager.attach(self) [attach alone shows HOME — no separate navigate] → AudioManager.play_bgm(BGM_MENU) → emit EventBus.app_ready. Root Window visibility_changed → EventBus.visibility_changed (AudioManager self-connects to it; main only forwards).
- **Headless forced-exit audio leak = accepted engine artifact (2026-11-03)**: Godot 4.7 headless `--quit-after` while BGM was started reports 2 leaked ObjectDB instances (AudioStreamWAV + AudioStreamPlaybackWAV) + 1 resource-in-use (bgm_menu.wav). Proven engine-side via minimal repros (never-played player = clean exit; explicit early stop() does NOT help — release happens in AudioServer mix processing which never completes at headless forced exit). No script-level fix exists. Decision: gate allows exactly these two documented lines; AudioManager still stops players in `_exit_tree()` as correct practice. Full evidence chain in NOTES.md.
- **Save mutation pattern**: read domain via SaveSystem.get_domain (copy), mutate, set_domain back, save_game(); emit EventBus.currency_changed / profile_updated for UI refresh.
- **UI framework (2026-11-03)**:
  - `BaseScreen` (screens/ui/base_screen.gd): full-rect preset + auto-connects `LocalizationManager.locale_applied` → virtual `_apply_locale()`; subclasses override it, never manage the connection. Non-screen widgets (header/nav/banner) connect to locale_applied themselves where they have text.
  - `PlayerInfoHeader`: reads "profile" domain; live via EventBus.profile_updated + currency_changed("coins"/"gems"). **XP curve placeholder: xp needed = level × 100** (`XP_PER_LEVEL` const); bar shows `xp % XP_PER_LEVEL`. Avatar = first letter of name.
  - `NavButton`: code-first, `setup(screen_id, label_key)`; shell connects pressed → EventBus.navigation_requested; `set_active()` drives the gold toggle state without emitting navigation.
  - `BannerAdSlot`: **non-loaded states (idle/loading/error) render an empty panel** — no translation keys for those states, and layout must not jump. Loaded creative: StyleBoxFlat override from `color_hex`, text color by luminance (`0.299r+0.587g+0.114b > 0.6` → COLOR_INK else WHITE). Hides itself entirely when `AdManager.is_enabled()` is false.
  - New translation keys: `header_coins`, `header_gems` (en/es).
  - `ScreenShell` (2026-11-03; scripts/ui/screen_shell.gd + core/screen_ids.gd): fractional-rect chrome consts; **shell owns L/R zones and ALL offer-claim logic** (Home stays ladder+PLAY only). Offer availability per kind: daily_gift = profile.last_daily_claim_day != today; piggy_bank = live "piggy_bank" domain balance > 0 (re-read each tick); others = cooldown elapsed or never claimed. Claim guard: stamps written ONLY when granted amount > 0 (protects save state from zero-amount config). Offer JSON field is `reward_currency` (NOT `currency`). Each offer additionally gated by `<id>_enabled` RemoteConfig flag (default true). New key `offer_ready_in` ("Ready in %d:%02d" / "Listo en %d:%02d"). Chrome state derived solely from screen_changed; fullscreen (GAME/RESULTS via ScreenIds.is_fullscreen) hides header/nav/banner/zones. BannerAdSlot manages its own visible → shell wraps it in a host Control and toggles the host. Nav buttons use SIZE_SHRINK_CENTER vertical flag.
- **ScreenManager (core/screen_manager.gd)**: autoload, NO class_name. Owns the single ScreenShell (`attach(host)` mounts full-rect + shows HOME). Screens lazily created per id, cached in a Dictionary and REUSED — swap does `remove_child` WITHOUT queue_free (cached instances must survive; BaseScreen's guarded locale reconnect makes re-_ready safe). `screen_changed` emitted AFTER the content swap. Match factory arms for all 7 ids (HOME/PROFILE/SOCIAL/SPECIAL/SETTINGS/GAME/RESULTS) + `_` catch-all warning fallback.
- **Godot 4 `tr()` API (VERIFIED by compiler)**: `tr(message, no_translation=false)` — at most 2 args, NO format-args overload. Formatted translations = `tr("key") % [args]`. Bare `match x: pass` is invalid — a match needs clauses; catch-all arm `_ : push_warning(...)` + explicit return.
- **Screens (2026-11-03)**: subclass pattern = override virtuals `_build_ui()` / `_apply_locale()`; `BaseScreen._ready()` does full-rect preset → guarded `_build_ui()` (once per instance, `_ui_built` flag — Godot fires `_ready()` on every re-entry and screens are cached/reused) → guarded `locale_applied` connect (`_locale_connected` flag) → `_apply_locale()`. Subclasses never manage the locale connection or call `_build_ui()` themselves. Every other signal connect is guarded (`is_connected` check) and `_exit_tree()` disconnects + calls super — screens are cached/reused, never freed. Stage persists in profile domain key `"stage"` (default 1; NOT in SaveSystem defaults — read via `get_value("profile", "stage", 1)`). Settings screen is signal-driven: controls never own state; `_apply_locale()` re-sets ALL tr() text incl. dialog (stale-text rule); reset order = clear_save → reset_to_defaults (emits all 4 settings signals, which re-localizes + re-syncs) → re-emit profile_updated + currency_changed×2 → no explicit apply_locale needed. Social feed gated by `social_feed_enabled` flag with empty-state label fallback. ConfirmationDialog parented to the screen so it can't overlay other screens. **Gotcha**: a missing `class_name` line = silent no-registration (empty label in import's update_scripts_classes step) → "Identifier X not declared" in referencing files; check `.godot/global_script_class_cache.cfg` when debugging.

- **Testing approach (2026-11-03)**: GUT 9.7, tests in res://tests/, run via `-s res://addons/gut/gut_cmdln.gd -gdir=res://tests -gexit`. Decisions: (a) whitebox underscore access into singletons is acceptable for a prototype test suite (faster than adding public getters everywhere); (b) fake `IAnalyticsBackend` as an inner class in each analytics-touching file — keeps assertions off disk; (c) every file that touches SaveSystem/RemoteConfig uses throwaway files under `user://gut_tmp` with `Time.get_ticks_usec()` stamps (msec stamps collide between fast before_each calls) and restores original paths in after_each; (d) expected push_error/engine errors are consumed explicitly with assert_push_*/assert_engine_error because GUT fails tests on unconsumed ones (warnings don't fail); (e) each file is fully self-contained — GUT runs the whole directory alphabetically in ONE process so singleton state persists across files.
- **AdManager STATE_LOADED fix (2026-11-03, found by GUT suite)**: `_refresh()` success path advanced the creative but never emitted `STATE_LOADED`, leaving the machine stuck in "loading" — BannerAdSlot only renders on STATE_LOADED, so the banner was permanently empty. Decision: emit `_set_state(STATE_LOADED, _current_creative)` after a successful load (after the ad_impression track), matching the error branch's track-then-emit order. The state machine contract in the file header (idle → loading → loaded | error) is now actually honored.
- **AudioManager duck/unduck rewrite (2026-11-03, found by GUT suite)**: original `tween_method(_set_bus_volume, from_db, target_db, fade)` was doubly broken — Godot's MethodTweener passes ONE interpolated value but `_set_bus_volume` takes two (bus_index, db), so every step errored and the Music bus never ducked (BGM stayed full-volume during gameplay). Additionally, `tween_method` with a BOUND callable is itself broken in Godot 4.7 (args mangled: probe received `(step_counter, 1.0)`). Decision: dedicated plain one-arg tween target `_set_music_bus_db(volume_db)` that resolves the Music bus index internally; shared helper `_fade_bus(bus_name, target_db, fade_sec)` with an explicit instant path for `fade_sec <= 0` (zero-duration tweens never run their callbacks — same fix applied to stop_bgm).
- **`.po` Language headers (2026-11-03)**: en.po/es.po lacked the `Language:` header field; Godot then registered BOTH under locale "en" (es shadowed, tr() returned Spanish under "en"). Added standard headers (`Project-Id-Version` + `Language: en|es`). LocalizationManager code was never at fault — its `get_loaded_locales()` guard worked exactly as designed.

- **UI pass part 2 (2026-11-03)** — layout changes + overlay services:
  - **Header layout**: gems LEFT / avatar+name+level CENTER / coins RIGHT (user-specified). XP bar removed from the header; xp remains in the profile save domain for when a real progression UI lands.
  - **Settings toggles replace volume sliders** (user-specified): SettingsManager gained `music_enabled` / `sfx_enabled` / `notifications_enabled` / `reduced_vfx_enabled` flags with per-flag signals, no-op setters, persistence and reset emission. Volumes stay internal (not exposed in UI) so a future fine-tune UI can reuse them without schema changes. AudioManager reacts to the enabled signals: disabling music stops BGM (remembering `_bgm_resume_track`), re-enabling resumes; SFX is gated at play time. `stop_bgm()`'s test-locked semantics (immediate clear, no auto-resume on visibility) were preserved — resume-on-re-enable lives in the toggle handler, not in stop_bgm.
  - **UIManager as an autoload with a CanvasLayer (layer 10)**: overlay content must float above ALL screens including fullscreen GAME/RESULTS, and screens are cached/reused (never freed), so a screen-parented host wouldn't work. One autoload owns four hosts (DialogHost, TooltipHost, ToastHost, TutorialHost) in z-order; hosts get PRESET_FULL_RECT on the layer so their local coords == viewport coords (input hit-testing stays trivial). UIManager is the ONLY public surface — screens call `UIManager.push_toast(...)` etc., never reach into hosts.
  - **Toast gate design**: toasts carry an optional `allowed_in_fullscreen` flag; a gate callable (set by UIManager) returns false while a dialog is open or the current screen is fullscreen, and blocked specs stay in the queue — re-checked on `EventBus.screen_changed` and `dialog_closed`. `toast_shown`/`toast_dismissed(text, tapped)` signals for analytics/testing. Tap runs the spec's optional action (e.g. navigate) or quick-dismisses when absent.
  - **Tooltip dismissal is deferred** (`call_deferred("dismiss")`): the spawning tap already passed the input phase, so any press seen in `_input` is a NEW interaction; deferring lets that interaction's GUI processing finish first. Dismissed also on navigation (UIManager._on_screen_changed).
  - **TutorialHost input model**: the highlight layer (MOUSE_FILTER_STOP) swallows every event except a press inside the target's global rect; that press is forwarded to the target (`Button.pressed` / `CheckBox.toggled`, or a step's custom `on_interact`) and advances. Multi-step sequences run in order; `refresh_target()` on navigation cancels when a step's target left the tree. `_process` re-tracks the hole/text every frame (targets can move with layout).
  - **Portrait customization is mock data in code** (`PortraitCatalog`: 6 icons / 7 flairs [ring/banner/capsule] / 4 crowns, all ThemeFactory colors + label_key); picks persist as plain strings in the "profile" save domain and refresh everywhere via `EventBus.profile_updated`. Chosen over .tres resources because it's prototype content that will be replaced wholesale by real art; the swap point is PortraitView/ProtoIcon only.
  - **Social screen is mock-data** (const arrays for friends/teams/chat) but the TEAM state is real: join writes a "team" save domain (`on_team`, `team_name`, `banner_color`, `power`, `members`) and the Team tab renders from it, so the on/off-team flow + CTA→Search handoff work end-to-end. Player starts NOT on a team (CTA visible).
  - **Zone widgets = big icon + small banner across it**, capped at 6 per side (`MAX_ZONE_WIDGETS`): each widget is an equal-height slot (EXPAND_FILL) with a centered 56px ProtoIcon and a 20px status strip pinned across the icon's bottom edge (overlapping by 8px, extending ±35% past the icon so localized countdowns like "Termina en 14:59" fit). Events' banner = dark strip + countdown caption; offers' banner = compact claim Button ("Claim" / "Claimed" / "Ready in m:ss"). **No panel backgrounds** — zones are invisible containers and widgets have no card panels (first iteration used EXPAND_FILL PanelZone cards, which read as huge blocks; user rejected). Offers gained an `icon` field in remote_config.json. The claim toast carries the reward message (`toast_reward`).
  - **Screen content anchoring (bug fix, found via user screenshots)**: TWO stacked bugs made every screen render as a small corner block at top-left instead of filling the content area (the shell chrome was fine because ScreenShell uses `_pin`):
    1. Every screen's root MarginContainer was added WITHOUT anchors — an unanchored Control shrinks to its minimum size at top-left. Fix: pin before `add_child` in all 7 screens' `_build_ui()`.
    2. THE REAL ROOT CAUSE (found via headless layout probe + minimal repro, 2026-11-03): `BaseScreen._ready()` pinned the SCREEN node with `set_anchors_preset(PRESET_FULL_RECT)` — but called AFTER tree entry, Godot 4.7 keeps the node's current (zero) rect by back-computing `offset_right/bottom = -parent_size`, permanently locking every screen to 0x0. The margin fix alone could never help because its parent was 0x0. Fix: `BaseScreen._ready()` now writes anchors/offsets explicitly (the `_pin` pattern); the GOTCHA is documented in base_screen.gd's header + NOTES.md so no future code pins via preset after tree entry.
  - **Home ladder centering**: `CenterContainer` (full rect) around the fixed-width ladder column — deterministic two-axis centering once the screen actually fills its area.
  - **Toasts wired into real flows** as first usage: offer claims (ScreenShell) and portrait picks (ProfileScreen, announces the localized item name).
  - **Privacy/Support buttons open UIManager text dialogs** with translated body text (new keys) rather than native OS dialogs — keeps everything in-theme and testable headless.
  - **Overlay hosts must be MOUSE_FILTER_IGNORE when idle (bug fix, found by user on first real boot)**: DialogHost/TutorialHost are full-rect Controls on the layer-10 CanvasLayer; with the default STOP they swallowed every click in the game even with nothing displayed. All four UIManager hosts are now IGNORE; interactive children (dialog backdrop, tutorial highlight layer, toast roots) use STOP only while visible.

- **Sub-page anchoring + animated offer widgets (2026-11-04)**:
  - **Tab sub-pages pinned full-rect BEFORE `add_child`** (same contract as BaseScreen's margin pin): Profile's 4 tab pages and Social's 3 tab pages live in plain (non-container) hosts, and Social's Team Chat/Members sub-pages live in a plain host inside the team content. Unpinned, each collapsed to its minimum size at top-left — the same failure class as the original "content stuck top-left" bug, one level deeper.
  - **Social search bar full width** was not a search-bar bug: the LineEdit already had `SIZE_EXPAND_FILL`; it only looked narrow because its page was collapsed. Fixing the page pinning stretched it to the page width automatically (verified: 1150px in a 1256px page next to the 98px mode OptionButton).
  - **Autowrap label min-width bound**: `_no_team_label` got `custom_minimum_size.x = 260.0` — an autowrapped label with ~0 min width wraps one char per line during min-size computation and inflates any full-rect ancestor to its (huge) min height (Team page measured 1300px tall vs a 689px host).
  - **OfferSpriteWidget** (scripts/ui/offer_sprite_widget.gd): Control host + centered AnimatedSprite2D for sprite-art offers. Scale = host_size / LARGEST frame side across ALL clips (frames vary within a clip; scaling against the max guarantees no frame overflows the square). The looping `idle` clip plays ambiently after `setup()`; `play_opening()` runs the one-shot `opening` clip for claim feedback, then returns to looping idle on `animation_finished`. Looping is controlled PER-CLIP via `SpriteFrames.set_animation_loop(anim, bool)` — AnimatedSprite2D has no `loop` property (verified by introspection); the authored loop state of the shared SpriteFrames resource is restored after the one-shot.
  - **ScreenShell icon routing**: `_add_widget()` returns an `OfferSpriteWidget` for remote-config icon keys `"gift"`/`"bank"` (Daily Gift, Piggy Bank) and a code-drawn `ProtoIcon` for everything else; offer-claim success plays `play_opening()` on the widget when present. Frame resources: `assets/sprites/gift_sprite_individual_frames/gift.tres` and `.../piggybank_individual_frames/piggybank.tres` (idle 6 frames + opening 7 frames @ 5fps each). **piggybank.tres was created by the user in the editor — do not regenerate it.**
  - **Layout regression tests** live in test_profile_social_screens.gd (pages/sub-pages fill their hosts on a phone-sized 720x1280 test host; search bar spans the page) and test_offer_sprite_widget.gd (resource clips, fit scale, idle advance, one-shot opening round-trip, shell routing).

- **Source of truth: GDD + TDD (2026-11-04, user directive)**: `documentation/GDD.md` (design intent + normative specs) and `documentation/TDD.md` (technical contracts) are now the single source of truth for framework design. **Both must be updated BEFORE implementing any new feature**; DECISIONS.md keeps the rationale history, NOTES.md the gotchas/verified APIs, TODO.md the status.

- **Warnings-as-errors + one-command gate (2026-11-04, ROADMAP A1+A2)**: `project.godot` `[debug] gdscript/warnings/treat_warnings_as_errors=true` — AGENTS.md promised this and it was never configured; now the import stage of the gate fails on ANY warning. All ~30 inventoried warnings were fixed properly (renames, explicit types, static calls); the one suppression is EventBus's file-level `@warning_ignore("unused_signal")` because the analyzer cannot see cross-file autoload signal usage — a false positive, not a real unused signal. **`tools/gate.sh`** = import → boot → full GUT with a single exit code; it is the Definition of Done (ROADMAP DoD section). It immediately paid for itself: the first green run after the screen_shell timer rework caught a nested-array `String % Array` formatting bug that import and unit tests both missed.

- **XP/level loop (2026-11-04, GDD §5)**: XP earned per round = coins earned (one "round value" source of truth — no second reward formula to drift). Curve `xp_needed_for_level(L) = 100 + 50×(L−1)` in `Scoring` (static, testable, shared by gameplay/results/profile). Application is centralized in GameScreen `_on_round_ended`: add XP, cascade level-ups while XP suffices, persist both to the "profile" domain. Feedback: `EventBus.level_upped(new_level)` (signal already existed, now actually used) + a "Level N!" toast with `allowed_in_fullscreen=true` because the round ends on fullscreen Game → Results and the moment of leveling is exactly when a blocked toast would be invisible. Profile → Stats shows level + XP progress toward the next level; Results shows "+N XP". The old header XP bar (`XP_PER_LEVEL = level × 100`) was already removed in UI pass 2 — superseded, not migrated.

- **Piggy bank deposits (2026-11-04, GDD §6)**: each completed round deposits `max(1, coins_earned / 5)` into the "piggy_bank" domain, capped at `piggy_bank_capacity` (remote value, default 200). Rationale: the bank previously had NO earning source — balance only ever decreased via claims, so the Piggy Bank offer could never be claimed and `piggy_bank_capacity` was dead config. The minimum-1 rule keeps the offer reachable even after barren rounds (a jar that only fills on good rounds feels broken in a 30-second-round prototype); the cap bounds growth while the player ignores it. Deposit lives next to coin crediting in `_on_round_ended` so one code path owns all round rewards.

- **FTUE v1 (2026-11-04, GDD §8)**: two steps on Home-owned controls — ladder title ("Climb the Adventure Ladder…", tap advances) then the PLAY button ("Tap PLAY to start your first round!", press forwarded → round starts). Runs from `HomeScreen._ready()` when `meta.ftue_done` is unset. **Bookkeeping placement (the non-obvious part)**: completion must be recorded in step 2's `on_interact`, NOT via `tutorial_finished` — the forwarded Button.pressed runs navigation synchronously, and ScreenManager unmounts Home (running `_exit_tree`, which disconnects) BEFORE TutorialHost emits `tutorial_finished`. The cancel path (leaving Home mid-FTUE; the tutorial auto-cancels when its target leaves the tree) is covered by `_exit_tree` marking `meta.ftue_done` when the flag isn't set yet. Both paths converge on one `_mark_ftue_done()` (meta domain + save_game). During an active tutorial all input outside the highlighted rect is swallowed, so in v1 the only exits are completing step 2 or programmatic navigation — no skip button needed.

- **TutorialHost freed-target hardening (2026-11-04, found by the FTUE tests)**: a test that frees the screen hosting a tutorial's target exposed that `var target: Control = step.get("target", null)` raises an engine error when the stored node has been FREED (typed assignment of a freed instance) — `_process` then errored every frame. Fix: all four read sites (refresh_target/_process/_show_step/_gui_input) go through `_current_target()` which reads a Variant, guards with `is_instance_valid()`, and only then casts; `_process` additionally self-cancels the tutorial when its target is gone or left the tree (previously only the screen_changed-driven `refresh_target()` did that). Production behavior unchanged (screens are cached, never freed) — this makes the host robust to any future caller whose targets get freed.

- **Campaigns + Events split, Special slot (2026-11-04, collaborative design with user)**: the Home left zone previously mixed "events" with no mechanics. Locked design: **events = multiplayer surface** (tournaments/races; display-only in this prototype) vs **campaigns = solo mechanics** — deliberately SEPARATE mechanisms "even if they surface similarly to the player" (user). Campaign entry shape: `action` = `"claim"` (reward_currency/reward_amount) | `"modifier"` (modifies coins|xp + multiplier) | absent (display-only); optional `ends_in_hours` (absent/≤0 = evergreen) and freeform `metadata` dict — framework-known keys `zone` ("left"|"right", user: placement "should be part of the event metadata"), `progress` {current, goal} → "N/M" strip, `dialog` {title, body} → tap opens a UIManager text dialog; unknown keys ignored (prototype extension point). Deadlines moved INTO RemoteConfig (computed at fetch/cache-load; whitebox `_event_deadlines`/`_campaign_deadlines`; `is_*_active(id)`, unknown id = inactive) so the shell no longer recomputes per rebuild and expired entries can be reaped live. Widget strip priority: claim button > progress > countdown > none (icon-only). **Lifecycle rule (user 4a)**: a widget disappears when its entry expires (1s tick check) or is claimed, and is filtered at rebuild; claims are once-per-id via the new `campaign_claims` save domain. Modifier campaigns apply at round END only (GDD §6 order: base_coins × ∏coins-mods → xp = coins_earned × ∏xp-mods), stack multiplicatively, and are surfaced on Results as "×N Title" badges (`GameResult.modifiers_applied`) so "the user is clear what is happening" (user). **Special screen (user 1c/3b)**: it "differs per prototype", so the framework ships a SLOT not content — new `BaseSpecialScreen extends BaseScreen` with virtuals `_build_special_content(host)` / `_refresh_special_content()`; default SpecialScreen keeps the title+body placeholder; prototypes BRANCH THE REPO and rewrite special_screen.gd (no runtime registration). Zone flags (`events_zone_enabled`/`offers_zone_enabled`) gate whole zones, not individual content — pre-existing semantics, now documented.

- **DevTools debug panel (2026-11-04, collaborative design with user)**: the least-designed foundational system (zero code, zero spec — audit ranked it above tooltips/dialogs). Locked answers: access = tilde key OR 3-finger downward swipe ("to support both editor and device testing"); gating = `OS.is_debug_build()` only (no remote flag); scope = save tools + config/experiment tools + system mirrors + telemetry + ad tools, **deliberately NO screen-navigation jumps** (navigation stays player-driven); form = overlay panel + testable autoload service. Architecture: `core/dev_tools.gd` (autoload, layer-20 CanvasLayer above UIManager) owns the gesture state machine + overlay lifecycle + ALL actions as plain methods (headless-testable); `scripts/ui/dev_panel.gd` is a thin UI caller, rebuilt on every open so it never shows stale config. **Inline confirmation** for reset-all instead of `UIManager.show_dialog`: the dialog host lives on layer 10, BELOW this overlay — a UIManager dialog would render behind the panel. Strings are en-only by design (dev tool, not user-facing; no tr()). - **FTUE "stuck on tutorial" fix (2026-11-05, user-reported: "cannot click the highlighted screen space, cannot click off of the tutorial")**: TWO stacked input-delivery bugs in TutorialHost. - **H2 Toast policy (2026-11-09, Phase H item 2)**: the removals themselves were already in code from earlier sessions (each former call site carries an "(H2)" comment); this pass was audit + pinning. Decisions: (1) **Policy statement** — toasts are for secondary/unexpected outcomes ONLY (failures, level-up, gift-pile reveal rewards); a direct effect of a tap (claims, collects, purchases, profile picks, code copy) never toasts — inline feedback instead (the dialog's opening clip, row/header state, label swap). Written into TDD §3.12 (Toasts bullet) and the GDD claim/purchase/profile lines, which still described the pre-H2 "toasts the reward" behavior. (2) **The pin that matters is the QUEUE, not the signal** — while a dialog is open the toast gate blocks showing (`_can_show_toast` → false), so a regression that re-adds a success toast to a claim flow would NOT emit `toast_shown` during the dialog; it stays queued and pops right after close (exactly the UX bug H2 fixed). Every zone-dialog claim test therefore asserts BOTH `assert_signal_not_emitted(toast_host, "toast_shown")` AND `queued_count() == 0` after close (close → `_on_dialog_closed` → `process_queue()` is synchronous, so no settle frame is needed). Flows pinned: daily-gift free claim, piggy IAP collect, streak claim, booster claim, campaign claim, shop purchase success; the counter-pin is shop insufficient-balance STILL toasting (failure = unexpected outcome). (3) **Code-copy pin avoids the headless clipboard trap** — `DisplayServer.clipboard_get()` in a headless run pushes an engine error ("Method/function failed. Returning: String()") that GUT fails as Unexpected Errors; `clipboard_set` is a silent no-op. The test therefore asserts only the observable inline feedback (label swap to `profile_code_copied` + restore after the 1.2s beat) and never reads the clipboard back. Gate 467→468.

- **B3 Performance guardrails (2026-11-09, ROADMAP Phase B item 3)**: lightweight audit per the item's own scope ("only add pooling if real content shows it's needed"). Decisions: (1) **No pooling** — the only allocation site in a frame callback is tap-target spawn (ColorRect + StyleBoxFlat), which fires at most every ~1.2s with ≤4 live nodes; a pool would be dead weight until a continuous-spawn mechanic exists, and the stress test's live-node assertion is already the guard. (2) **The one fix** — `GameScreen._refresh_hud()` deduped on the FORMATTED string (`"%s: %d" % [tr(...), score]` built every frame just to compare), so every frame paid for a tr() locale lookup + array literal + two string allocations even when nothing changed. Now it compares raw ints and formats only on change; `-1` sentinels reset in `_apply_locale` preserve the locale-switch re-render. (3) **Profiling approach = three tiers, matching what this environment can actually do** — headless gate: `test_stress_long_session` as the perf regression guard (real frame pumping + live-node-count bound); on-device: a new DevTools TELEMETRY `fps` line (snapshot on panel open — deliberately NOT a per-frame `_process` reader, keeping the debug overlay allocation-free when closed); deep breakdowns: editor profiler under Xvfb (`xvfb-run -a ~/tools/godot -e --path .` → Debugger → Profiler), because the headless dummy renderer has no frame pacing and cannot produce meaningful CPU numbers. All three documented in NOTES.md "Performance guardrails" with the conventions to keep (early-out `_process`, cached refs, raw-value dedupe, event-boundary allocations).

- **B1 Android export preset + gate step (2026-11-09, ROADMAP Phase B item 1)**: made "it builds for mobile" a per-change check instead of a ship-time surprise. Decisions: (1) **Debug preset only** — the goal is verifying the build pipeline on every change; release signing/keystore management waits for actual shipping (the release template + same toolchain are already in place, so `--export-release` is one preset option away). (2) **Non-gradle template build** — Godot's prebuilt `android_debug.apk` template + aapt2/d8/apksigner from build-tools 34.0.0, no Gradle/AGP involved: fastest path and it sidesteps the AGP-vs-JDK-version matrix entirely (JDK 25 works fine for this path — verified). `gradle_build/target_sdk` must stay empty in that mode (engine error otherwise). (3) **arme64-v8a only** — every phone we'll test on is arm64; shipping armv7/x86 doubles the APK for zero prototype value. (4) **ETC2/ASTC compression enabled project-wide** (`rendering/textures/vram_compression/import_etc2_astc=true`) — mandatory for Android export; full re-import stayed clean (zero new warnings), so the gate's warnings-as-errors rule still holds. (5) **Gate greps `ERROR:` only in the export step** — apksigner under JDK 25 prints java `WARNING:` lines (restricted native access) that are harmless; failing on them would couple the gate to JVM warning text. The adb "cannot connect to daemon at tcp:5037" line is likewise noise (no device attached). (6) **Vendored AdMob C# samples excluded from export** (`exclude_filter="addons/admob/csharp/*"`) — they are C# scene/script pairs the GDScript-only editor can't parse; 62 ERROR lines per export until excluded. The plugin folder itself stays unmodified per the H10 hermeticity decision. (7) **Toolchain locations fixed in NOTES.md** rather than hardcoded in gate.sh beyond `ANDROID_HOME`-style env overrides — the SDK/templates/keystore/JDK are machine-level, not project-level; the gate reads them from the standard places (`~/Android/Sdk`, Godot editor settings).
