## Known engine artifact: headless forced-exit audio leak (Godot 4.7, build 5b4e0cb0f)
Boot test (`--quit-after 60`) with BGM playing reports exactly:
```
WARNING: 2 ObjectDB instances were leaked at exit ...   (object.cpp:2535)
ERROR: 1 resources still in use at exit ...             (resource.cpp:822)
```
Verbose names them: `AudioStreamWAV` + `AudioStreamPlaybackWAV` (refcount 1 each), resource = `res://assets/audio/bgm_menu.wav`, plus harmless `Orphan StringName: Music`.

**PROVEN engine artifact, NOT project code** — minimal repros (2026-11-03, all in a throwaway dir since deleted):
| Repro | Setup | Result |
|---|---|---|
| A | bare `AudioStreamPlayer`, stream set, `autoplay = true`, forced quit 60 frames | leaks (same 2+1) |
| B | same + script calls `player.stop()` at t=0.5s, quit at t=1.0s | **still leaks** — explicit early stop does NOT release them |
| C | stream assigned but player NEVER plays | **clean exit, zero messages** |

Mechanism: releasing the playback happens inside AudioServer's mix processing; in headless forced-exit that never completes for a started playback, so `AudioStreamPlaybackWAV` (which refs the `AudioStreamWAV`) survives ObjectDB cleanup. No script-level API forces the release. `AudioManager._exit_tree()` still stops players + kills the fade tween (correct practice; just can't beat the engine's teardown order).

**Gate definition**: boot test passes when output contains NO errors/warnings OTHER than these two documented lines (+ the verbose-only orphan StringName). Any NEW message = regression.

## Gotchas
- **`func` is a GDScript reserved word** — cannot be a parameter name.
- `TranslationServer.get_loaded_translations()` does NOT exist in Godot 4.7 → use `loaded_locales` property (array).
- Type inference from autoload method calls FAILS if that autoload script has parse errors (cascades) — fix root cause AND add explicit types for robustness.
- GDScript int = signed 64-bit: hex literals wrap negative; `%` can be negative → normalize `(x % 100 + 100) % 100`. Reason RemoteConfig uses its own FNV-1a instead of engine `hash()`.
- Edit tool: re-read file before editing; oldString must match EXACTLY (incl. indentation).
- tscn format=3 in Godot 4.7. Code-first UI: minimal .tscn, build UI in GDScript.
- Autoload scripts must NOT use class_name; non-singletons do.
- GUT v9: verify method names by grepping `addons/gut/test.gd` (NOT gut_test.gd) before writing tests.
- **Godot 4.7 parse quirk**: `OS.has_name("android")` inside a STATIC function fails to parse ("Static function has_name() not found in base GDScriptNativeClass") even though `OS.get_name()` works there — use `OS.get_name() in ["android", "ios"]` instead (bites AdMobBackend.is_supported_platform).
- **Vendored plugins must stay DISABLED in editor_plugins while the gate is hermetic**: the AdMob plugin's `EditorPlugin._enter_tree()` calls `BinaryInstaller.install_missing_binaries_sync()`, which DOWNLOADS Android/iOS binary zips whenever `DisplayServer.get_name() == "headless"` (its CI-export convenience). Enabling it would make `--import`/boot network-dependent. Its `class_name` API is available without the EditorPlugin; enable only when prepping a real mobile export (follow-up TODO).

### Godot 4.7 engine gotchas (verified this session, 2026-11-03)
- **`.po` files REQUIRE a `Language:` header field.** Without it, Godot registers the translation under locale "en" regardless of filename — with en.po + es.po both headerless, `get_loaded_locales()` returned `["en"]` and tr() served Spanish strings under the "en" locale (es silently shadowed). Both files now carry `Language: en|es`.
- **`JSON.parse_string()` returns ALL numbers as FLOAT** in 4.7 (probe: `typeof(JSON.parse_string("123"))` = TYPE_FLOAT). Save roundtrips turn ints into floats; compare with tolerance or cast at the boundary. It ALSO emits an engine error ("Parse JSON failed...") on malformed input — GUT counts that as an unexpected error, so tests exercising corrupt JSON must consume it with `assert_engine_error("Parse JSON failed")`.
- **`tween_method()` + bound Callable = broken in 4.7.** `tween_method(m.bind(x), from, to, dur)` calls the method with mangled args (probe: received `(step_counter, 1.0)` instead of the interpolated value; no error logged). Plain one-arg callables work fine. Workaround in AudioManager: `_set_music_bus_db(volume_db)` resolves the bus index inside the method.
- **Zero-duration tweens never complete their callbacks.** `tween_property(..., 0.0)` + `tween_callback(stop)` leaves an AudioStreamPlayer "playing" forever (next play_bgm then takes the crossfade path and delays fade-in by FADE_SEC). AudioManager has explicit instant paths for `fade_sec <= 0` in stop_bgm/duck_music/unduck_music.
- **`create_tween()` before the node's `_ready`** (e.g. inside a SceneTree `_initialize` probe) produces a tween that never steps — warm up with `await create_timer(...)` before probing audio behavior.
- **Full-rect Controls on a high CanvasLayer default to `mouse_filter = STOP` and swallow ALL game input** even when they display nothing (verified 2026-11-03: UIManager's dialog/tutorial hosts made the whole game unclickable until set to `MOUSE_FILTER_IGNORE`). Every always-present overlay host must be IGNORE; interactive CHILDREN (backdrop, highlight layer, toast roots) opt back into STOP only while visible.
- **Unanchored Control children shrink to their minimum size at top-left.** Every screen's root container (MarginContainer) must be pinned full-rect BEFORE `add_child` — all 7 screens had this bug (content rendered as a small corner block; found via user screenshots 2026-11-03). The layout contract is documented in base_screen.gd's header.
- **`set_anchors_preset()` AFTER tree entry silently locks the control to 0x0 (Godot 4.7).** Verified with a minimal repro (`tools/probe_minimal.gd`, 2026-11-03): preset set before `add_child` → fills parent; preset set in `_ready()` (node already in tree) → Godot keeps the node's current (zero) rect by back-computing `offset_right/bottom = -parent_size`, and the control stays 0x0 forever — re-calling the preset does NOT fix it (it recomputes from the poisoned offsets). Explicit anchor/offset writes (`node.offset_right = 0.0` etc., the `_pin()` pattern) DO work even after tree entry. This is why `BaseScreen._ready()` pins the screen with explicit property writes instead of `set_anchors_preset()`, and why it was the REAL root cause of the "content stuck top-left" screenshots (the margin pinning alone couldn't help: its parent, the screen node itself, was 0x0).
- **Headless layout probing**: `tools/probe_layout.gd` boots the real main scene headless (`-s res://tools/probe_layout.gd`) and prints global rects/anchors of shell + Home containers. Caveats: headless window is square (1280x1280) so `expand` stretch makes content 1280 wide — check RELATIVE positions, not absolute widths; `root.size` reads (64,64) in headless (unreliable), use control rects.
- **New `class_name` scripts need an `--import` pass before anything can reference them** — the global class cache (`.godot/global_script_class_cache.cfg`) only refreshes on import; referencing a fresh class without it gives "Could not find type X" parse errors that CASCADE into every file that parses after it.
- **`-s` SceneTree tool scripts run WITHOUT autoloads** — one-shot tools (`tools/build_theme.gd`, `tools/build_stages.gd`) must not reference singleton names; duplicate the needed constants locally (e.g. build_stages carries its own STAGES_DIR).
- **Calling a function that contains `await` WITHOUT awaiting it runs it as a suspended coroutine** — the caller continues immediately while the callee pauses at its first `await`. In probe scripts this masqueraded as a game bug: a report function suspended mid-way, later navigation legitimately detached the screen it was still reading (verified 2026-11-04). Always `await` such calls.
- **Never name a script method `show()` or `is_visible()`** — they collide with native CanvasItem members; with warnings-as-errors the shadow warning becomes a compile failure ("Could not resolve external class member"). This is why DialogHost uses `open()`/`open_text()` and TooltipHost uses `has_tooltip()`.
- **`Vector2 * float` returns a Vector2, not a float** — scalar multiplication is valid, so `u := size * 0.5` infers `u` as Vector2 and every later use of `u` where a float is expected (e.g. `draw_circle(pos, u * 0.16)`) is a type error. For a unit scale use `size.x * 0.5`.
- **SpriteFrames/AnimatedSprite2D API (4.7, verified by introspection 2026-11-04)**: there is NO `get_animation_list()` — it's `get_animation_names() -> PackedStringArray`. AnimatedSprite2D has NO `loop` property and NO `current_animation` — the current clip is the `animation` property (or `get_animation()`), and looping is PER-CLIP on SpriteFrames: `set_animation_loop(anim_name, bool)` / `get_animation_loop(anim_name)`. GDScript parses unknown property access on typed objects fine and only fails at runtime ("Invalid access to property or key"), so a widget can look healthy in import/boot and blow up when the bad line actually executes — tests exercising the real code path are what catch it.
- **`AnimatedSprite2D` is a Node2D, not a Control** — no `mouse_filter`; it never takes GUI input. Wrap it in a Control host (OfferSpriteWidget) for layout/GUI purposes.
- **Containers do NOT sort hidden subtrees** — child rects inside a hidden container stay at minimum/zero size until the subtree becomes visible (verified 2026-11-04: Social Team sub-pages measured 0x0 while their page was hidden). Probes/tests that measure nested layout must first make the whole ancestor chain visible, then await frames.
- **Autowrapped Label with ~0 min width explodes VERTICALLY in min-size computation** — wraps one character per line at 1px width → min height of thousands of px, which clamps any full-rect anchored ancestor UP to that size (verified 2026-11-04: Social Team page inflated to 1300px tall). Fix: give the label a bounded `custom_minimum_size.x` (pattern: TutorialHost's text label; SocialScreen uses 260.0).
- **Assigning a FREED instance to a typed variable is an engine error** — `var target: Control = dict.get("target", null)` raises "Trying to assign invalid previously freed instance" the moment the stored node has been freed (verified 2026-11-04: TutorialHost `_process` errored every frame after its tutorial target screen was freed). The validity check must happen BEFORE the typed assignment: read into a `Variant`, guard with `is_instance_valid(value)`, then cast (`value as Control`). Pattern lives in `TutorialHost._current_target()`.
- **`String % Array` formatting: pass the args array directly, never wrap it** — `tr("key") % [a, b]` works; `tr("key") % [[a, b]]` (accidental nested array) fails at runtime with "String formatting error: a number is required" while still passing import/boot. Caught by the boot stage of tools/gate.sh (screen_shell timer text, 2026-11-04).
- **Key constants in Godot 4.7 GDScript (verified against 4.7-stable source + probes)**: there is NO `KEY_TILDE`/`KEY_BACKQUOTE` member on the `Key` type — parse errors both bare and prefixed. The bound names (from `core/core_constants.cpp`, `BIND_CORE_ENUM_CLASS_CONSTANT`) are **`Key.KEY_ASCIITILDE` (0x7e = 126, logical tilde)** and **`Key.KEY_QUOTELEFT` (0x60 = 96, the physical backquote key)**. - **A full-rect overlay host with `mouse_filter = STOP` swallows ALL input even while it shows nothing** — the DevTools overlay root defaulted to `visible=true` and would have blocked every tap in the game before the first open; the lifecycle test caught it. Always initialize such hosts HIDDEN (`visible = false`) and only show them when there is actually content (same class as the UIManager host gotcha, but for on-demand overlays).
- **GUI mouse events are delivered to the TOPMOST non-IGNORE Control under the pointer — not to every ancestor.** A parent's own `_gui_input()` never fires while a STOP child covers the pointer (verified 2026-11-05: TutorialHost's full-rect `_HighlightLayer` consumed every tap, so the host's handler was dead and FTUE froze on step 1). Pattern: the topmost child emits a signal (`input_received(event)`) and the parent connects to it. Note `gui_find_control` walks per-CANVAS-LAYER root subtrees (a Control is a "root" only while it has no Control ancestor), sorted canvas-layer-then-tree-order, topmost first — so a full-rect STOP child on a higher CanvasLayer always wins over same-screen controls regardless of tree position.
- **`gui.mouse_focus` is cleared the moment the focused control exits the tree** (`Viewport::_gui_remove_control` on EXIT_TREE), and a mouse RELEASE is only delivered to `gui.mouse_focus` — so if press handling destroys/replaces the overlay MID-EVENT (`queue_free` old, `add_child` new) and the release lands after the frame ends, the release is SILENTLY LOST. Any sticky per-tap state cleared only on release then sticks forever (verified 2026-11-05: a `_press_handled` dedupe flag froze the tutorial — every subsequent press was swallowed; repro'd headless by pushing down+up with `await process_frame` between). Dedupe statelessly instead: one physical tap on touch devices ALSO emits an emulated mouse event (and vice versa with `emulate_touch_from_mouse`) carrying `device == InputEvent.DEVICE_ID_EMULATION (-1)`; real touches are 0, real mice 32 (`DEVICE_ID_MOUSE`). TutorialHost swallows the emulated twin — no flag, nothing to lose.
- **Whitebox tests that call a GUI handler directly bypass hit-testing** — they pass even when real input can never reach the handler (the stopped-child bug above shipped with green tests). Regression coverage for "input reaches the overlay" must push events through `get_tree().root.push_input(event, true)` and await frames between down/up; see `test_ftue_advances_with_real_viewport_input` + `tools/probe_tutorial_input.gd`.
- **`_ready()` fires ONLY on the FIRST tree entry in Godot 4.7 — re-adding a cached node does NOT re-fire it** (verified 2026-11-09 with a remove/re-add probe: `_ready` count stayed 1 while `NOTIFICATION_ENTER_TREE` went to 2, for both spaced and synchronous re-add). This contradicts the common Godot-3 assumption and was the root cause of H5 (Gift Pile's second RV climb showed the previous run's stale result pane because its entry logic lived in `_ready()`). Consequences: (a) any screen that must refresh when ScreenManager re-shows it has to hook `EventBus.screen_changed` itself (pattern: `GiftPileScreen._on_screen_changed`, first emission skipped); (b) a signal connected in `_ready()` and disconnected in `_exit_tree()` is DEAD after the first navigation away — `_exit_tree` fires on every leave but `_ready` never re-runs to reconnect, so for cached-forever screens the connection must be kept for the instance's whole life (destroying the object auto-disconnects). `base_screen.gd`'s header documents the corrected behavior.

### Godot 4.7 GDScript typing & coroutine facts (verified 2026-11-06)
- **A function typed `-> Array[Dictionary]` (or any typed array/dict) CANNOT `return null` in Godot 4.7** — it is a parse error, and `null` is the natural "transport failed" signal for fallible interface methods. Interface pattern: fallible methods return **`Variant`**; success payloads keep their documented types, `null` = failure (documented at the source in i_social_backend.gd's header).
- **Calling a coroutine that has a TYPED RETURN VALUE without `await` is a parse error** ("Function X() is a coroutine, so it must be called with await"). A VOID coroutine that only awaits ready (non-signal, non-pending) values completes SYNCHRONOUSLY in the same call stack (probe-verified) — which is why existing tests can call screen methods like `_on_join_pressed(...)` un-awaited while backends are synchronous; but any code path needing a typed-return coroutine's value MUST `await`.
- **`String.is_digits()` does NOT exist in Godot 4** (parse error) — validate digits with an explicit char-range loop.
- **`int(string, base)` does NOT exist in Godot 4.7 GDScript** (parse error — `int()` takes a single value; there is no radix constructor) — parse fixed-base strings with a manual char loop or avoid them (`String.to_int()` is base-10 only).
- **TabContainer's signal is `tab_changed(int)` — there is NO `current_tab_changed`** (connecting the wrong name aborts `_build_ui` mid-way and cascades null-control errors into every later test). It also fires when the FIRST tab child is added, so anything that reacts to it (timers, state) must exist BEFORE pages are added.
- **GDScript `.get(key, {})` returns a THROWAWAY default dict when the key is missing** — `typeof(x) != TYPE_DICTIONARY` checks pass and writes go into the throwaway, silently vanishing. Use `if not data.has(k) or typeof(data[k]) != TYPE_DICTIONARY: data[k] = {}` then return `data[k]` (bit the SaveSystem sync-stamp store).
- **Bare method-name access returns a Callable, not the value** (verified 2026-11-08): `arr.size` (no parentheses) is a method reference — formatting it with `%d` fails at runtime. The codebase idiom is `.size()` (the call); keep it.
- **Explicitly-typed variables reject duck-typed test fakes at RUNTIME** (verified 2026-11-08): `var client: NakamaClient = OnlineService.get_client()` compiles fine but raises "Trying to assign value of type ''" when a test injects a duck-typed FakeClient. Annotate `Variant` instead (explicit `Variant` dodges the UNTYPED_DECLARATION warning under warnings-as-errors) — applied in tournament_service.gd + dev_tools.gd.
- **A fake's `rpc_async` must return REAL `NakamaAPI.ApiRpc` instances** (verified 2026-11-08): `NakamaAnalyticsBackend` is ALWAYS attached and, in real mode, assigns its rpc result to an `ApiRpc`-typed variable — a duck-typed FakeRpc fails at runtime. Use `NakamaAPI.ApiRpc.create(NakamaAPI, {"payload": ...})` for success and `NakamaAPI.ApiRpc.new(NakamaException.new(msg, code))` for failure (pattern in test_tournament_service.gd).
- **`Color()` defaults to OPAQUE BLACK (alpha 1.0) in Godot 4.7 — NOT transparent** (verified 2026-11-08 via a throwaway probe: `COLOR_CHECK a=1.0 r=0 g=0 b=0`). Any "has tint" check written as `if _tint.a > 0.0` treats every default-constructed color as a black tint — this silently made ALL untinted ProtoIcons render pure black since the prototype began (icons looked like dark silhouettes in every probe screenshot). Correct sentinel: `_tint != Color()` (fixed in proto_icon.gd `_col()`/`_reload_texture()`; an intentional fully-transparent or exact-black tint is a pathological case, accepted). Use `Color.TRANSPARENT` when you actually want alpha 0.

- **`return;` is INVALID in Godot fragment shaders** — "Using 'return' in the 'fragment' processor function is incorrect" → `Shader compilation failed` engine ERROR every time a ShaderMaterial with that shader is created (GUT fails on it). ### GUT 9.7 semantics (verified this session)
- Unconsumed **push_error / engine errors FAIL the test**; unconsumed push_warning does NOT fail (still consume expected ones for determinism). Consume via `assert_push_error(text, msg)`, `assert_push_warning(text, msg)`, `assert_engine_error(text, msg)` — substring match, case-insensitive, each error assertable once.
- `clear_signal_watcher()` runs after EVERY test → call `watch_signals(obj)` fresh in each test that needs it; never rely on cross-test state. GUT runs `-gdir` files ALPHABETICALLY IN ONE PROCESS → singleton state persists across files; every file must set up/tear down its own temp save/config/cache paths (pattern: `user://gut_tmp/<file>_<Time.get_ticks_usec()>.json`, restore originals in after_each, remove `.tmp` siblings).
- Signal asserts: `assert_signal_emitted(p1, p2='', p3='')` (p3 = message); `assert_signal_emit_count(obj, sig, count)`; `assert_signal_emitted_with_parameters(obj, sig, [params], index=-1)` — **index -1 = LAST emission** (matters when one action emits a sequence, e.g. AdManager loading→loaded). ⚠️ The 4th arg is an INT index ONLY — there is NO trailing description-string overload (unlike the other asserts). Passing a String lands in `get_signal_parameters(index)` → "Invalid operands 'String' and 'int'" script error inside GUT + failing test.
- Async tests: plain `await wait_seconds(t)` works in test/before_each; GutTest is in the scene tree so `add_child()` works.
- `assert_file_exists(path)` takes NO message parameter (parse error if you pass one) — use `assert_true(FileAccess.file_exists(p), msg)`.
- `assert_almost_eq(got, expected, error_interval, text='')` — interval REQUIRED; use for JSON roundtrips (floats) and bus dB values.
- Whitebox underscore access (`SaveSystem._data`, `Analytics._queue`, `AdManager._creative_index`, `RemoteConfig._loaded`...) is an accepted test pattern in this prototype.
- **GDScript lambdas capture locals BY VALUE** — `var x := false; func() -> void: x = true` never mutates the outer variable (verified 2026-11-03 via a failing toast-tap test). Mutate through a reference container instead: `var state: Dictionary = {"x": false}; func() -> void: state["x"] = true`.
- **Cross-file singleton hygiene**: ScreenManager caches screens in `_screens` and holds `_shell`; when one test file frees its attach host, the NEXT file that re-attaches must reset BOTH (`if not is_instance_valid(ScreenManager._shell): ScreenManager._shell = null; ScreenManager._screens.clear()`) or attach() will re-add a freed cached screen instance.
- **GUT SILENTLY SKIPS a test file that fails to parse** (verified 2026-11-04): `-gdir` prints "Ignoring script ... because it does not extend GutTest" and the run still reports ALL-PASS with the missing file's tests absent from the count. A return-type change in production code (ScreenShell `_add_widget` Control → Dictionary) broke `test_offer_sprite_widget.gd`'s parse (`var gift := shell._add_widget(...)` inferred Dictionary, then `gift is OfferSpriteWidget` = static type conflict under GUT's stricter warnings pass) and the suite went 137→130 "green". Always diff the per-file list + total test count against the previous run after touching production signatures.
- GUT 9.7 has **no `assert_str`** (parse error if used) — use `assert_eq(String(x).get_file(), expected, msg)`; and GutTest has no `tree` property — await `get_tree().process_frame`. A test that `queue_free()`s its host must `await get_tree().process_frame` afterwards or GUT reports "N unfreed children" warnings.
- **GUT's "N unfreed children" check counts DIRECT children at end-of-script, with no frame between `after_all` and the check** (verified 2026-11-08 by reading gut.gd `_log_test_children_warning` + test.gd): GUT ITSELF adds an `_awaiter` node to every test script (test.gd `_do_ready_stuff` → `add_child(_awaiter)`), so the warning fires whenever ≥1 of YOUR children is still pending — i.e. a `queue_free()` in `after_all` is NEVER processed before the check. Warning-free pattern: `host.free()` (immediate, removes from tree) in `after_all` — that's why test_ui_skins is clean while queue_free-based suites all warn "2 unfreed children" (awaiter + host). - GUT 9.7 has **no `assert_dict` / `assert_dict_equals`** (verified by grepping the addon) — use `assert_eq(a, b, msg)` for deep container comparison (it is deep by default). Full assert inventory: assert_eq(_deep/_shallow), assert_ne(_deep/_shallow), assert_almost_eq/ne, assert_between/not_between, assert_gt/gte/lt/lte, assert_true/false/null/not_null/same/not_same/is, assert_typeof/not_typeof, assert_has/does_not_have, assert_called/call_count/not_called, assert_signal_emitted(_with_parameters)/not_emitted/signal_emit_count, assert_push_error/warning (+_count), assert_engine_error(+_count), assert_connected/not_connected, assert_freed/not_freed/no_new_orphans, assert_file_*, assert_exports/property/setget/accessors/readonly_property/has_method/has_string...
- GUT 9.7.1 **warning tracking**: `gut.get_warnings()` DOES NOT EXIST — use `assert_push_warning(text)` / `assert_push_warning_count(n, msg)` (each push_warning is assertable once; un-asserted warnings do NOT fail a test, but a SCRIPT ERROR from an invalid call does). GDScript inner classes CANNOT reference outer-scope functions/methods (parse error "Function not found in base self") — put helpers as static members of the inner class; `var x := <untyped expr>` fails type inference — annotate explicitly.
- Synthetic touch events: `InputEventScreenTouch` / `InputEventScreenDrag` have **NO `global_position` property** (mouse events only) — assigning it is an engine error that fails the test under GUT's error capture; `position` suffices (TooltipHost hit-tests global rects, and in tests local == viewport coords).
- **`SaveSystem.set_save_path()` does NOT reload** (verified 2026-11-08) — a test switching to a temp save path must also call `SaveSystem.load_save()`, or stale singleton state leaks across tests (bit the tournament suite: gems from an earlier file survived into the first test).
- **GUT `-gselect=<substring>` runs ONE file by name substring** (verified 2026-11-08: ran test_tournament_service.gd alone, 15/15) — but it takes a SINGLE substring; comma-separated lists are not honored. This is distinct from the `-gtest=<full path>` flag above, which does NOT narrow the run in this setup.
- **GUT `assert_signal_emitted_with_parameters(obj, sig, expected_params, index)` — the 4th positional arg is the EMISSION INDEX (int), NOT a failure-message string** like most other asserts take (verified 2026-11-09, E1): passing a description there makes GUT compare with a String index → engine error "Invalid operands 'String' and 'int' in operator '=='" surfaces as an "Unexpected Errors" test failure instead of a clean diff. - **Presence / status semantics (E2, live-verified 2026-11-09 — spike folded into the four `probe_nakama.gd` presence checks; probe total now 23/23)**:
  - **The FOLLOW ACK is the replay** (nakama v3.37.0 `server/pipeline_status.go` `statusFollow`): the ack to `status_follow` ALWAYS carries `Status{Presences}` = the followed users who are online RIGHT NOW. No JOIN push is sent for already-online friends — their current presence arrives in the follow RESPONSE, so `subscribe_presence` must emit an initial delta from `follow.presences` (username = player code) or those friends stay invisible until their next connect/disconnect.
  - **Go protojson omits empty repeated fields** → when ALL followed users are offline the ack has NO `presences` key at all. The stock addon schema (`NakamaRTAPI.Status`, `required: true`) turned that successful follow into a client-side deserialization exception — PATCHED to `required: false` in our vendored copy (comment cites the source). Probe pins both directions.
  - **LEAVE/JOIN pushes** (`received_status_presence` → `StatusPresenceEvent.joins/.leaves`): B disconnect → LEAVE on A; B reconnect → JOIN again (follow state persists server-side per socket). LEAVE carries no timestamp → we stamp last-seen = now.
  - **Visibility is harmless**: an `appear_online=true` socket receives status-presence events exactly like an invisible one — chat + presence share ONE always-visible socket (the spec's reconnection dance is unneeded).
  - **Godot 4.7 has NO app-close notification** — `MainLoop.NOTIFICATION_APPLICATION_CLOSES` does not exist (engine source `core/os/main_loop.h`: enum only covers 2009–2020; absent from the 4.3/4.7 class reference too). The app-exit last-seen stamp hooks `NOTIFICATION_PREDELETE` on the OnlineService autoload instead (fires when it is freed at shutdown; best-effort by design).

- **Matchmaking semantics (E4, source-verified against nakama v3.37.0 + live-probe-verified 2026-11-09; probe total 32/32 = 27 + five matchmaking checks)**:
  - **Matches form on a fixed interval** (`config.go IntervalSec`, default 15s — no compose override on the local stack): queue waits can reach ~15s → time-based bounds (up to 40s), never attempt-counted loops.
  - **`matched.users` includes SELF** — every MatchmakerUser row including your own; opponent rows = users minus self.
  - **Join ack `size` is racy for sequential joins** — both clients join after the matched event and the second ack may report size=1; membership proof is the match PRESENCE event, not the ack count.
  - **Match data round-trips op_code + base64 payload** (`send_match_state_async` → `received_match_state`; the addon's `.data` getter decodes).
  - **Query language differs across Nakama versions** — master's matchmaker is bluge-based (property-filtered queries), v3.37.0 uses a different query language; keep `"*"`. A stray third client on the shared local stack snipes a ticket and fails the "both see each other" assertion — which is exactly what a probe should flag.
  - **Client-side race: connection order matters** — `NakamaMultiplayerBridge._init` connects `received_matchmaker_matched` to auto-join, and Godot 4.7 completes `await <plain value>` SYNCHRONOUSLY (no frame suspension) → a handler connected after the bridge can observe QUEUED→IN_MATCH with empty opponents. The service connects its matched handler BEFORE constructing the bridge (dispatch order = connection order).
- **Banner LUT luminance remap (H3, render-verified 2026-11-09 via `tools/verify_banner_lut.gd`)**:
  - **Root cause of "multi-color LUTs only show the right-most color" = the ART, not the shader.** The index math in `banner_lut.gdshader` was verified correct by render readback (no off-by-one, correct uv axis). The sheet-split grayscale art is luminance-flat: icons sit in ≈0.43–0.81 everywhere (median ≈0.74), bases are a bright field ≈0.75–0.81 + thin dark frame <0.25. Raw 0–1 quantization therefore only ever hit palette indices ~11–12 (+frame-dark for bases) — every one of the 48 palettes rendered as one flat bright hue near the right end of its ramp, and the middle of every ramp (indices 5–10, where "multi-color" variety lives) was never used.
  - **Fix = input-luminance remap window in the shader** (`remap_lo=0.35`, `remap_hi=0.85` uniforms): stretch the art's actual luminance span onto the full 0–15 index range (below lo → darkest entry, above hi → brightest). Post-fix readback: base_15+lut_01 uses 14 of 16 indices (field idx 12–14 vs frame idx 0–4 = proper duotone), icon_01+lut_02 spans 11 distinct indices. The window is a floor, not a squeeze — real art with a wider luminance range simply uses more of its own spread.
  - **Authoring guidance for the future art pass**: keep shading/gradient/half-toning in bases and icons (the remap assumes ~0.35–0.85 working range); pure-flat single-tone art will always collapse to one palette entry no matter what.
  - **Verification is display-only** (`xvfb-run -a ~/tools/godot --path . -s res://tools/verify_banner_lut.gd`): the hermetic gate runs headless (dummy renderer, no pixels), so this tool is the pixel-level pin — re-run it after any shader or banner-art change.

## Performance guardrails (B3 — audited 2026-11-09)
Project rules (AGENTS.md): static typing mandatory; minimize `get_node()` in `_process` — cache node references in `_ready()`.

**Per-frame audit (all real `_process`/`_physics_process` methods)**: there are exactly four — `TutorialHost._process`, `TooltipHost._process`, `GameScreen._process`, `GameplayBase._process` (+ the gameplay virtuals). None call `get_node()`; all use cached references and early-out when inactive (tooltip returns immediately with no live long-press candidate; gameplay returns when not running/paused; tutorial returns while idle). Allocations are event-driven, not per-frame: tap-target spawns a ColorRect + StyleBoxFlat only at spawn time (~1.2–1.6s cadence, ≤4 alive) — **pooling NOT added** (B3 rule: only when real content shows it's needed; revisit if a future mechanic spawns continuously). One real finding, fixed in B3: `GameScreen._refresh_hud()` formatted strings every frame (`"%s: %d" % [tr(...), score]` + `str(seconds)`) even when values were unchanged — it now dedupes on the raw ints (`_last_score` / `_last_seconds_left`, -1 sentinels reset in `_apply_locale` so a locale switch re-renders) and only formats on change.

**Profiling approach for this project**:
- **In-gate regression guard (headless)**: `tests/test_stress_long_session.gd` pumps 8 real-time rounds through the actual GameScreen under dense churn — its live-node-count assertion (`≤ MAX_TARGETS`) + ~9s wall time catch per-frame leaks and O(n) drift. Extend it when a new hot path appears.
- **On-device snapshot**: DevTools TELEMETRY section shows an `fps` line (snapshot on panel open; `Engine.get_frames_per_second()`). Open the panel (`~` / 3-finger swipe) in-game to sanity-check frame rate without a debugger.
- **Deep breakdown (CPU/memory)**: run the editor under Xvfb — `xvfb-run -a ~/tools/godot -e --path .` → Debugger → Profiler (Frame/Node/Memory tabs). The headless gate cannot profile (dummy renderer, no frame pacing), so any performance question that needs real numbers goes through this path or a device.
- **Conventions to keep**: early-out `_process` on inactive state; cache references in `_ready()` (no `get_node()` per frame); dedupe per-frame writes on RAW values (int/float), never by formatting the display string first; allocations belong at event boundaries (spawn/tap/claim), not in frame callbacks.
