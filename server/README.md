# server — Nakama server stack (D5b)

Server-side companion to the Godot framework in `../framework/` (TDD §3.17/§3.18, BACKEND.md).
Pinned upstream Nakama 3.37.0 + Postgres 16 + Caddy. **No core fork** — custom
code is (a) the one JS server function in `functions/index.js` (Nakama 3.x has a
SINGLE JS entrypoint at `runtime.path/index.js`; the RPC id comes from
`registerRpc("team_ops", ...)`) and (b) the analytics Go plugin in
`plugins/analytics/`, compiled to `functions/analytics.so` and auto-loaded by
Nakama from the same `runtime.path` (official extension point; `.so` files are
discovered alongside `index.js`).

## Layout

| Path | Purpose |
|---|---|
| `docker-compose.yml` | LOCAL dev stack (plain HTTP, dev key defaults) |
| `docker-compose.prod.yml` | VPS stack (TLS ports, secrets required — fail fast) |
| `Caddyfile` | Local: `:8080` api (static `/config` + proxy→Nakama). Prod version is GENERATED by deploy.sh |
| `.env.example` | Copy to `.env`; local defaults are safe for the dev machine only |
| `functions/index.js` | The ONE JS server function (`team_ops` RPC): group create/update with metadata (REST can't write metadata) + owner enforcement. ES5 only (goja VM); flat runtime context (`ctx.userId`) |
| `plugins/analytics/` | Analytics Go plugin source (`main.go`, `go.mod`, `build.sh`). Exposes RPC `analytics`; writes the `analytics_events` table into Nakama's own Postgres |
| `functions/analytics.so` | Built artifact of the plugin (output of `plugins/analytics/build.sh`); auto-loaded by Nakama. Rebuild after ANY Nakama version bump |
| `config/remote_config.json` | Served at `/config/remote_config.json` — the live remote config (edit → clients pick up on refetch) |
| `deploy.sh` | VPS runbook: generates `.env` secrets + prod Caddyfile, starts stack, verifies |
| `backup.sh` | Nightly `pg_dump` archive (+ optional rclone offsite) |

## Local development

```sh
cd server
./plugins/analytics/build.sh   # build the analytics plugin into functions/
docker compose up -d
# client settings (project.godot [game]):
#   backend_base_url = http://localhost:8080
```

Verify: `curl http://localhost:8080/healthcheck` → `{}` (200 = healthy, body is empty);
`curl http://localhost:8080/config/remote_config.json` → config;
nakama logs show `Found runtime modules ... ["index.js","analytics.so"]` and
`Registered Go runtime RPC function invocation "id":"analytics"`.

Headless probe from the game repo (needs a running stack):

```sh
cd ../framework
~/tools/godot --headless --path . -s res://tools/probe_nakama.gd \
    -- --host localhost --port 8080 --scheme http
```

Tear down: `docker compose down` (add `-v` to wipe the database volume).

## Analytics sink (Go plugin — no second container)

The analytics sink is a Nakama **Go plugin** (`plugins/analytics/`), NOT a
separate service: it registers RPC `analytics`, and the client's
`NakamaAnalyticsBackend` posts each flush batch to it. The handler writes rows
into an `analytics_events` table in Nakama's own Postgres (identity comes from
the authenticated session context — the client never sends user identity).
Zero extra containers, zero extra credentials; query later with
`docker exec backend-postgres-1 psql -U postgres -d nakama -c '\dt'`.

**Version pinning (critical):** a Go plugin must be compiled with the EXACT
toolchain that built the Nakama binary. Nakama 3.37.0 is built with **Go 1.25.5**
and `nakama-common v1.44.2`; `build.sh` pins both (`golang:1.25.5` image,
`go.mod`). Bumping the Nakama image tag = bump BOTH pins and rebuild, or Nakama
fails to start with `plugin was built with a different version of package
internal/goarch`.

**Build flag gotcha:** the plugin MUST be built with `-trimpath` (build.sh does
this). The official Nakama binary is built with `-trimpath=true`, which rewrites
source paths baked into each stdlib package's export-data fingerprint; without
matching `-trimpath` on the plugin, the runtime's per-package hash check fails
with the same `internal/goarch` error even when Go versions match.

Payload contract (client → RPC): `{"events":[{"name","ts","session_id","props"}]}`
— max 500 events/call, name ≤128 chars; `ts<=0` stores NULL; `props` is raw JSON
(JSONB). Response: `{"ok":true,"count":N}`.

## Deploy (4GB VPS)

```sh
# on the box, server/ copied to /opt/backend:
cd /opt/backend
API_DOMAIN=api.yourdomain.com ./deploy.sh
# nightly backups:
15 3 * * * cd /opt/backend && ./backup.sh >> /var/log/nakama-backup.log 2>&1
```
